> **Work-AI Bridge** — легковесный прокси-мост с нулевыми внешними зависимостями для безопасного проброса трафика [Google Antigravity IDE](https://antigravity.google/), Cursor, Claude Code, Copilot и других AI-инструментов с изолированной рабочей машины (через RDP) на домашний ПК с выходом в свободный интернет (AmneziaVPN, WireGuard и др.).

---

## 🎯 Проблема и решение

### Проблема
* Вы работаете на корпоративной рабочей машине удаленно через **RDP** без прав администратора.
* На рабочей машине доступ к публичным AI API (Google Gemini, Claude, OpenAI) заблокирован корпоративным фаерволом или шлюзом.
* Включение стороннего VPN прямо на рабочей машине **невозможно**: оно немедленно разорвет сессию RDP, заблокирует доступ к корпоративным ресурсам или нарушит правила безопасности (DLP).

### Решение
**Домашний ПК** уже подключен одновременно к двум сетям:
1. К корпоративной сети через корпоративный OpenVPN (чтобы подключаться к рабочей машине по RDP).
2. К свободному интернету (через AmneziaVPN / WireGuard / прямое подключение).

**Work-AI Bridge** запускается на домашнем ПК и открывает локальный порт (по умолчанию `8080`) внутри корпоративного VPN-туннеля. Рабочая машина направляет через него **исключительно трафик к AI-сервисам**, а весь корпоративный трафик (внутренний GitLab, Jira, базы данных, стенды) продолжает идти напрямую через корпоративную сеть благодаря правильной настройке `NO_PROXY`.

## ✨ Ключевые возможности

* 🚀 **Zero Dependencies**: Только чистая стандартная библиотека Python (`socket`, `threading`, `select`, `urllib`). Никаких `pip install`.
* 🧠 **Оптимизировано под LLM и Streaming**:
  * Включен двунаправленный **TCP KeepAlive** (опрос каждые 3 сек при простое более 10 сек) — фаерволы не сбрасывают сессию во время длительных "размышлений" модели (Extended Thinking).
  * Таймаут ожидания стриминговых ответов (SSE, gRPC) увеличен до **30 минут**.
* 🔍 **Smart Network Discovery**: Автоматически сканирует сетевые адаптеры, определяет IP-адрес домашнего ПК в корпоративном VPN и сразу генерирует готовые команды для копирования на рабочую машину.
* 🛡️ **Безопасность корпоративных данных (DLP-friendly)**:
  * Прозрачный HTTPS CONNECT туннель: мост **не расшифровывает** TLS-трафик и не требует подмены сертификатов (End-to-End шифрование между IDE и Google).
  * Все внутренние ресурсы компании исключаются из проксирования через `NO_PROXY`.
* 🩺 **Предстартовая самодиагностика**: При старте скрипт автоматически проверяет доступность `generativelanguage.googleapis.com` через внешний шлюз домашнего ПК.
* 🧹 **Автоматическое освобождение порта**: Если порт `8080` остался занят зависшим предыдущим процессом, скрипт корректно завершит его и запустит мост без ручного поиска в диспетчере задач.
* 🧪 **Полное тестовое покрытие**: В репозиторий включены автоматические unit- и интеграционные тесты (на базе `unittest`) и настроенный GitHub Actions CI.

## 🚀 Быстрый старт

### Шаг 1. Запуск на домашнем ПК

Убедитесь, что на домашнем ПК запущены:
1. Корпоративный VPN (OpenVPN клиент для связи с офисом).
2. Зарубежный шлюз (AmneziaVPN или другое соединение с доступом к AI API).

Запустите мост:
```powershell
python scripts/bridge_proxy.py
```
*(Или запустите двойным кликом файл `run_bridge.bat` в корне)*

Скрипт выполнит диагностику и выведет в консоль готовые команды с вашим реальным IP-адресом:
```text
============================================================================
      >>> WORK-AI BRIDGE PROXY (FOR ANTIGRAVITY & AI TOOLS) <<<      
============================================================================

[*] Обнаружение сетевых интерфейсов:
   * [OpenVPN Data Channel] : 10.x.x.x <--- (Определен как туннель OpenVPN)

[*] Проверка связи с upstream AI (https://generativelanguage.googleapis.com)...
   [УСПЕШНО] Upstream доступен! (Connection OK (HTTP 404))

[+] Прокси запущен на 0.0.0.0:8080 (Доступен для рабочей машины: 10.x.x.x:8080)
----------------------------------------------------------------------------
>>> ИНСТРУКЦИЯ ДЛЯ РАБОЧЕЙ МАШИНЫ (выполнять внутри RDP-сессии):
...
```

### Шаг 2. Настройка на рабочей машине (RDP)

На рабочей машине права администратора **НЕ нужны**. Все настройки производятся для текущей учетной записи пользователя.

> Замените `10.x.x.x` на адрес, выведенный скриптом на Шаге 1.

#### 1. Проверка доступности моста
Откройте PowerShell на рабочей машине и проверьте связь:
```powershell
curl.exe -I -x http://10.x.x.x:8080 https://generativelanguage.googleapis.com
```
*Ожидаемый ответ*: `HTTP/1.1 200 Connection Established`.

#### 2. Установка переменных окружения (User-level)
Выполните в PowerShell на рабочей машине:
```powershell
[System.Environment]::SetEnvironmentVariable("HTTP_PROXY", "http://10.x.x.x:8080", "User")
[System.Environment]::SetEnvironmentVariable("HTTPS_PROXY", "http://10.x.x.x:8080", "User")
[System.Environment]::SetEnvironmentVariable("NO_PROXY", "localhost,127.0.0.1,*.company.com,*.corp.internal", "User")
```
> [!IMPORTANT]
> В `NO_PROXY` обязательно укажите доменные суффиксы вашей компании (например, `*.mycompany.corp,*.gitlab.mycompany.ru`), чтобы трафик к репозиториям и базам данных шел напрямую, минуя домашний ПК.

#### 3. Настройка интерфейса Antigravity IDE
1. В Antigravity IDE откройте **Settings** (`Ctrl + ,`).
2. В строке поиска введите `proxy`.
3. Задайте параметры:
   * **Http: Proxy**: `http://10.x.x.x:8080`
   * **Http: Proxy Support**: `override` (или `on`)
4. Перезапустите IDE для применения настроек.

## ⚙️ Параметры командной строки

Вы можете тонко настроить запуск прокси-моста через флаги CLI:

| Флаг | Описание | По умолчанию |
| :--- | :--- | :--- |
| `-p`, `--port` | Порт для прослушивания входящих подключений | `8080` |
| `-b`, `--host` | Адрес для привязки сокета | `0.0.0.0` |
| `--ip` | Вручную указать IP-адрес для отображения в инструкциях | *Автоопределение* |
| `--corp-domains` | Список внутренних доменов для `NO_PROXY` | `*.corp.yourcompany.com` |
| `--skip-probe` | Пропустить предварительную проверку связи с AI API | `False` |
| `--probe-url` | URL для предстартовой проверки связи | `https://generativelanguage.googleapis.com` |
| `--log-file` | Файл журнала запросов (пустая строка для отключения) | `bridge_traffic.log` |
| `--stream-timeout` | Таймаут (в секундах) для удержания стриминговых сессий LLM | `1800` (30 мин) |

### Пример запуска с параметрами:
```powershell
python scripts/bridge_proxy.py --port 9090 --corp-domains "*.mycompany.ru,*.corp.local"
```

## 🧪 Запуск автотестов

В проекте реализованы модульные и интеграционные тесты без сторонних зависимостей. Они проверяют:
* Эвристики распознавания корпоративных туннелей (10.x, 172.x, игнорирование Amnezia/Radmin/Docker).
* Логику проверки связи с Google AI.
* Обработку CLI-аргументов.
* TCP KeepAlive на сокетах.
* Реальный проброс HTTP GET и HTTPS CONNECT туннелей с обработкой ошибок (502 Bad Gateway).

Для запуска тестов выполните в корне репозитория:
```bash
python -m unittest discover -s tests -v
```
*(Или запустите двойным кликом файл `run_tests.bat`)*

## 🤖 Интеграция со Skills в Antigravity

В репозиторий включен файл [SKILL.md](./SKILL.md), полностью совместимый со спецификацией **Antigravity Customization System**.

Чтобы агент Antigravity на рабочей машине знал обо всей инфраструктуре моста, умел сам тестировать связь и помогать в диагностике:
1. Скопируйте папку репозитория в каталог скиллов Antigravity:
   * **В рабочем пространстве проекта**: `<ваш_проект>/.agents/skills/work-ai-bridge/`

2. Агент автоматически активирует скилл при запросах по настройке сети, прокси или диагностике соединения с моделями Gemini.

## 🩺 Диагностика и устранение неполадок

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| `curl: (28) Failed to connect / timed out` | Брандмауэр Windows на домашнем ПК блокирует входящий порт | Добавьте входящее правило брандмауэра на домашнем ПК (PowerShell от администратора):<br>`New-NetFirewallRule -DisplayName "Work-AI-Bridge" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow` |
| `HTTP 502 Bad Gateway` при запросе curl | Домашний ПК не может достучаться до серверов Google AI | Проверьте подключение AmneziaVPN на домашнем ПК. Убедитесь, что предстартовый probe в консоли выводит `[УСПЕШНО]`. |
| Сменился IP-адрес домашнего ПК | Корпоративный OpenVPN переподключился и выдал новый динамический IP | Перезапустите `bridge_proxy.py`. Он покажет новый IP в строке Network Discovery. Обновите адрес в `HTTP_PROXY` и настройках Antigravity. |
| Обрыв длинных ответов через 1–2 минуты | Промежуточный NAT сбрасывает неактивное TCP-соединение | Убедитесь, что запускаете актуальную версию `bridge_proxy.py`: в нее встроен активный TCP KeepAlive на уровне ядра ОС. |

## 🔒 Безопасность и этика

* **Защита исходного кода компании**: Благодаря маске `NO_PROXY` внутренний трафик компании никогда не покидает корпоративный контур. Мост используется только для внешних запросов к AI API.
* **Отсутствие MITM**: Прокси работает в режиме туннелирования (`CONNECT`), передавая байты напрямую между клиентом и удаленным сервером. Никаких самоподписанных сертификатов не генерируется и не устанавливается.
* Проект предназначен для повышения личной продуктивности разработчиков в соответствии с политиками безопасности вашей компании.
